# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Project

Сайт Т-Парка (t-camp.ru) на Python 3.14 + Django 6.1: публичная витрина (шаблоны + Tailwind) и админка Unfold. Старая Flask-версия — в `old_version/` (только для справки и импорта, не менять; исключена из ruff и pre-commit). Спецификация — `docs/superpowers/specs/2026-10-08-django-rewrite-design.md`, журнал решений — `docs/decisions.md`, старый функционал — `docs/current-functionality.md`. Весь пользовательский текст — на русском.

## Layout

- `src/` — весь Django-проект: `pyproject.toml`/`uv.lock`, `manage.py`, `config/`, `apps/`, `templates/`, `static/`, `tailwind/`, `tests/`. Dev-окружение (`.venv`, `.env` из `src/.env.example`, по умолчанию `db.sqlite3` и `media/`) тоже живёт в `src/`. Копия реального контента — в корне, `current_content/` (`db.sqlite3` + `media/`): подключается через `DATABASE_PATH`/`MEDIA_ROOT` в `src/.env`.
- Корень — инфраструктура: `Dockerfile`, `compose.yaml`, `docker/`, `scripts/`, `.env.example` (продакшен, для compose), `.pre-commit-config.yaml`, `docs/`, `old_version/`.

## Commands

Основное есть в корневом `Makefile` (`make help`): `make install`, `make run`, `make test`, `make check`, `make dev`, `make up`, `make backup`.

Python-команды запускаются из `src/`:

```bash
cd src
uv sync                                   # зависимости (включая dev)
cp .env.example .env                      # dev-окружение (DEBUG=1)
uv run manage.py migrate
uv run manage.py tailwind runserver       # dev-сервер + пересборка Tailwind (бинарник скачается в src/.django_tailwind_cli/)
uv run pytest                             # все тесты (settings: config.settings_test)
uv run pytest tests/test_pages.py::test_info_page   # один тест
uv run ruff check . && uv run ruff format .
uv run manage.py import_legacy --db ../old_version/T_Park.db --images <папка images со старого сервера> [--flush]
```

Из корня репозитория:

```bash
uv run --project src pre-commit run --all-files   # ruff в pre-commit закреплён той же версией, что в src/uv.lock; docs/ и old_version/ исключены
docker compose -f compose.dev.yaml up --build --renew-anon-volumes  # локально в Docker: http://localhost:8000, DEBUG=1, src/ примонтирован (hot reload + Tailwind watch); -V — .venv из нового образа
docker compose -f compose.dev.yaml exec tpark-dev python manage.py createsuperuser
docker compose up -d --build                      # продакшен (корневой .env из .env.example, нужна внешняя сеть PROXY_NETWORK); обновление — `make up` (сборка, бэкап работающего сайта, запуск)
docker compose -f compose.nginx.yaml up -d --build # продакшен без общего прокси: свой nginx на 80/443, сам выпускает сертификат Let's Encrypt (README)
make service-install && make service-deploy        # продакшен без Docker: systemd-юнит + gunicorn на unix-сокете (deploy/, README)
```

## Architecture

Пути ниже — относительно `src/`.

- `apps/core` — настройки сайта (синглтон `SiteSettings.load()` + `Phone` с флагами WhatsApp/Telegram, не более одного номера на флаг — ограничение в БД и `PhoneFormSet` в админке), инфо-страницы и общие хелперы:
  - `fields.py` — `HtmlField` (prose-editor с очисткой nh3; `sanitize_html` — та же очистка для импорта), `photo_field` (пережатие при загрузке), `image_spec` (WebP-миниатюра) и `image_specs` (WebP + AVIF-двойник `<спека>_avif`: `card, card_avif = image_specs(...)`), `full_spec` (лайтбокс: WebP 1920), `og_spec` (og:image: JPEG 1200×630 — соцсети не понимают AVIF), `UploadTo` (случайные имена файлов);
  - `images.py` — `safe_spec_url`, `picture_html` (тег `{% picture %}`), `lightbox_url`, стратегия imagekit `GenerateAfterCommit` (`IMAGEKIT_DEFAULT_CACHEFILE_STRATEGY`): недостающая миниатюра создаётся при показе, а после сохранения фото все его миниатюры — сразу в фоновом потоке; backend `AtomicBackend` (`IMAGEKIT_DEFAULT_CACHEFILE_BACKEND`) пишет файлы атомарно, не запоминает ошибку генерации и в запросе пережимает не дольше `REQUEST_GENERATION_BUDGET` секунд (дальше — `GenerationDeferred`: `safe_spec_url` отдаёт пустую строку, `{% picture %}` — оригинал; иначе после смены спек галерея упиралась в таймаут gunicorn) (у `Simple` после исключения URL несуществующего файла отдавался до перезапуска); `prune_image_cache` удаляет миниатюры, не нужные ни одной текущей спеке (запускается в `docker/entrypoint.sh` после `generate_missing_images` — создаёт только недостающие миниатюры и пишет в лог одну строку, в отличие от `generateimages`; при пустой базе ничего не делает; папку `CACHE` целиком не удалять — imagekit кеширует «файл есть»);
  - `files.py` — удаление файлов и их миниатюр imagekit при удалении/замене записи, только после коммита (`on_commit`), чтобы откат не терял файлы;
  - `request_cache.py` — `cached_on_request`: значение один раз на запрос; через него `SiteSettings.for_request(request)` (контекст-процессоры, JSON-LD) и сами контекст-процессоры `site`/`menu`/`site_texts` (в админке Unfold они вызываются на каждый шаблон); справка SEO-вкладок (`SeoHelp` в `admin_utils.py`) подставляется в `SiteModelAdmin.get_fieldsets` тоже один раз на запрос (шаблон Unfold вычисляет описание дважды);
  - `rotation.py` — `daily_pick(items, k, key)`: подборка витрины, которая меняется раз в сутки (сид — дата + ключ страницы), а в течение дня одинакова во всех воркерах — ETag/304 не ломаются; порядок — как в исходном списке. Через него — полоса фото «Как это выглядит» (`GalleryPhoto.strip_photos`) и «Ещё в категории» на странице услуги;
  - инфо-страницы (`InfoPage`, `/info/<slug>/`): подзаголовок `lead` (он же description по умолчанию), фото в шапке `cover` (`cover_og` — og:image), оформление `layout` — «Текст» / «Правила» (раздел — карточка с номером, списки с галочками: `.rich-text-rules`) / «Вопросы и ответы» (H3 — `<details data-smooth>`); редактор с цитатой-выноской и таблицами — `INFO_HTML_EXTENSIONS` (только у `InfoPage.body`). `rich_text.py` (`parse_info_body`) при выводе делит текст по H2 на разделы с якорями (nh3 вырезает `id`), от трёх разделов — оглавление (`TOC_MIN_SECTIONS`), таблицы оборачивает в `.rich-table` с прокруткой; шаблоны — `core/info.html` + `core/partials/info_*.html`, внизу — `cta_card` с текстами `info.*`. Ссылки в подвале — галочка `show_in_footer` (контекст `footer_pages`, порядок — `order`, перетаскиванием в списке); `SiteSettings.safety_page` — только плашка на «О нас», `privacy_page` — ссылка в баннере cookie;
  - `maps.py` — поле встраиваемой Яндекс Карты (`MapEmbedURLField`: принимает код `<iframe>` или ссылку, только `yandex.ru/map-widget/`);
  - `seasons.py` + модель `Season` — сезонное оформление («Новый год», «Зима», «Осень»; набор фиксирован, записи — data-миграции `0023_create_seasons`, `0025_create_autumn`, недостающие создают открытие настроек в админке и `import_legacy`): даты «ДД.ММ» каждый год (конец может быть в следующем году), режим «По датам» / «Включено» / «Выключено»; «Включено» — даты подходят всегда, из подходящих — первый по `PRIORITY` (старший: Новый год → Зима → Осень); сезон не из `PRIORITY` пропускается. Контекст `season` → `<html data-season>`, весь декор — CSS (`tailwind/source.css`: фон `.page-hero`, слой `.season-particles` — снег или листья по `data-season`, гирлянда на Новый год; разметка — `partials/hero_decor.html`), логотип на сезон в шапке: загруженный → свой основной → нарисованный `static/img/logo-header-<kind>.png` (стандартный со снегом или листьями; перерисовать — `scripts/draw_season_logos.py`); в JSON-LD — всегда основной. Тесты идут 14.07.2026 (вне сезонов) — `today()` подменяет `tests/conftest.py`; inline «Сезонное оформление» в настройках сайта — сезоны табами (`templates/admin/core/season/tabs_inline.html`: обёртка над stacked-inline Unfold, видна одна форма; классы табов — из `unfold/helpers/fieldsets_tabs.html`, сверять при обновлении Unfold);
  - `Announcement` («Сайт → Плашки») — полоса с текстом и ссылкой под шапкой на всех страницах, от сезона не зависит: галочка «Показывать» + необязательные даты «с/по», показывается одна — первая по порядку (`Announcement.objects.current(day)`, контекст `announcement`, `partials/site_banner.html`: вересковая `bg-heather-100`, как карточки отзывов, — отличается по тону от кремовой, голубой и осенней шапок; со ссылкой — стрелка); под шапкой, а не над ней — иначе мобильное меню не влезает в экран;
  - `bulk_upload.py` — загрузка фото пачкой в админке; `legacy_redirects.py` — 301 со старых URL; `sitemaps.py` (`lastmod` из `updated_at`);
  - `redirects.py` + модель `Redirect` + `middleware.RedirectFallbackMiddleware` — смена slug (категория, услуга, мероприятие, инфо-страница) сама создаёт 301 со старого адреса (без цепочек; вернули прежний — редирект удаляется); отдаётся только на 404, живая страница важнее; правка вручную — «Сайт → Редиректы»;
  - SEO: `SeoModel` (поля `seo_title`/`seo_description`/`updated_at` у категорий, услуг, мероприятий, инфо-страниц; в админке — вкладка `SEO_FIELDSET` со справкой из `templates/admin/seo/` через `seo_help`, счётчиками символов и превью сниппета — `static/js/admin_seo.js`), `seo.py` (`make_seo` для объектов, `page_seo` для статических страниц с умолчаниями `PAGE_DEFAULTS`), `structured_data.py` (JSON-LD узлы; список в `structured_data` контекста → `@graph` через фильтр `ld_json`), `middleware.CanonicalHostMiddleware` (301 с www на `CANONICAL_HOST`). Canonical, `og:image` по умолчанию и Метрика — из контекст-процессора `site`; адрес парка — `PARK_ADDRESS`;
  - `privacy_defaults.py` — типовая политика конфиденциальности (152-ФЗ) с пометками «[укажите …]» для реквизитов: data-миграция `0014_privacy_policy` и импорт старой базы создают её снятой с публикации и выбирают в настройках (`privacy_page`);
  - `legacy/` — `import_legacy` (одна транзакция, отказ на непустой БД без `--flush`, отчёт с предупреждениями); `backup_db` — снимок SQLite.
  - `content_fixes.py` + команда `normalize_content [--apply]` — бренд «Т-Парк», «₽», единицы цен, кавычки в названиях, известные опечатки; цена услуги приводится к числу (без «руб»/«₽» — их добавляет витрина); без `--apply` только отчёт; запускать после финального импорта;
- `apps/catalog` — `CategoryGroup` ↔ `Category` (M2M) и `Category` ↔ `Service` через `CategoryService` с полем порядка. Меню (`menu_groups`) приходит из контекст-процессора; настройки и телефоны — из `apps.core.context_processors.site`.
- `apps/content` — мероприятия (`upcoming()` / `past_visible()` — многодневное с `end_date` считается предстоящим, пока не закончилось; метка «Через N дней» — `Event.timing`; черновики (`is_published=False`) — 404; страница `/events/<slug>/` открывается у всех опубликованных, но прошедшее без «Показывать после даты» — с `noindex` и вне sitemap и списков (`visible()`), slug из «заголовок + год», JSON-LD `schema.org/Event` через фильтр `ld_json`), отзывы (HTML, без имени — все «Гость Т-Парка»; кнопка «Подтянуть» в админке берёт текст и дату со страницы Яндекс Отзывов — `yandex.py` + `static/js/admin_review_fetch.js`, вставка в prose-editor через событие `prose-editor:ready`), партнёры, галерея.
- `apps/texts` — «Тексты сайта»: короткие фразы и заголовки блоков витрины (длинные HTML-тексты страниц — в `SiteSettings`). Набор — реестр `registry.py` (`TEXTS`: ключ `<страница>.<имя>`, название, текст по умолчанию, где на сайте, обязательность), значения — `SiteText`, вывод — `{% load site_texts %}{% text "ключ" %}` (экранирование + `nobr`) или `{% text "ключ" as имя %}` → `{{ имя|nobr }}`; все тексты — одним запросом (контекст-процессор `site_texts`), без записи — текст по умолчанию. Новый текст: строка в реестре + тег в шаблоне + data-миграция с `sync_texts` (тест `test_registry_matches_templates` сверяет реестр с шаблонами). История и «Восстановить» — `django-simple-history`; `templates/simple_history/object_history_list.html` — копия шаблона Unfold («—» вместо «None» у версии без автора), сверять при обновлении Unfold.
- Админки наследуются от `apps.core.admin_utils.SiteModelAdmin` (не напрямую от `unfold.admin.ModelAdmin`): она подключает `static/js/admin_unsaved.js` — предупреждение при уходе со страницы с несохранёнными изменениями (формы и списки с `list_editable`; встроенный `warn_unsaved_form` Unfold не ловит перетаскивание и списки), поиск — без учёта регистра и «ё»/«е» (`apps/core/search.py`: SQL-функция `tp_fold` на каждом подключении к SQLite; `LIKE` SQLite не различает регистр только у латиницы).
- Главная админки — `templates/admin/index.html` (копия шаблона Unfold + быстрый старт `admin/dashboard_help.html`), сверять при обновлении Unfold. В шаблонах админки работают только Tailwind-классы, собранные в CSS Unfold (нет, например, `list-decimal`, `space-y-1`).
- Рамка админки: кнопка «Открыть сайт» справа в шапке — `templates/unfold/helpers/userlinks.html` (копия шаблона Unfold); переключатель темы в меню профиля — `templates/unfold/helpers/theme_switch.html` + `theme_switch_option.html` (сегменты «иконка над подписью», в боковой панели уже 240 px — только иконки; тест — `tests/e2e/test_admin_chrome.py`); общие стили — `static/css/admin.css` (`UNFOLD["STYLES"]`: высота боковой панели в `dvh`, иначе на телефоне профиль внизу уходит под панель браузера). Сверять при обновлении Unfold.
- Справка админки — `/admin/help/` (`apps/core/admin_help.py`: `HELP_SECTIONS`, по шаблону на раздел в `templates/admin/help/sections/`, стили — `static/css/admin_help.css`), пункт «Справка» вверху бокового меню. Над списками — вводная `help_intro` и ссылка на раздел `help_anchor`, над формами — «Справка по разделу» (атрибуты `SiteModelAdmin`, шаблоны `admin/help/list_intro.html`, `form_link.html`); тест требует их у каждого раздела бокового меню. Меняешь поведение, заметное администратору (публикация, фото, порядок, новые поля и разделы), — обнови раздел справки, вводную и `help_text`.
- Перетаскивание файлов во все поля загрузки админки — `static/js/admin_dropzone.js`, подключён через `UNFOLD["SCRIPTS"]` (работает и на кастомных страницах вроде загрузки пачкой); рассчитан на разметку виджетов Unfold, поэтому свои файловые поля делаем на `UnfoldAdmin*FieldWidget` (как `MultipleImageInput`).
- У Unfold нет русской локали: недостающие строки переводятся в `locale/ru/LC_MESSAGES/django.po` (`LOCALE_PATHS`); после правки — `uv run manage.py compilemessages -l ru` (нужен gettext), `.mo` коммитится.
- Порядок везде — `order` + перетаскивание Unfold (`ordering_field`). Неопубликованное — 404.
- Единый стиль витрины — классы в `tailwind/source.css` (`@layer components`): шапка страницы `.page-hero` + `partials/hero_decor.html`, `.page-title`/`.page-lead`, `.eyebrow` (зелёный надзаголовок раздела) и `.field-label` (серая подпись поля), `.card`/`.card-link` (обводка `ring-1` — тень снаружи блока: в контейнере с `overflow` у карточек нужен запас, иначе её срезает), `.scroll-strip` — лента карточек со свайпом на телефоне. Цвета по смыслу: оранжевый (brand) — только кликабельное; зелёный (pine) — «природа и место» (`partials/find_us_card.html`, статусы, надзаголовки); navy — информационные иконки; серый текст — только `ink/75` и `ink/65` (`ink/55` и светлее не проходят контраст WCAG 4.5:1).
- Фото витрины — тегом `{% picture obj "спека" %}` или `{% picture obj "спека_640 640w, спека_800 800w" sizes="…" alt="…" class="…" %}` (`{% load site_tags %}`): `<picture>` с AVIF-двойниками в `<source>` и WebP в `<img>` (без двойника — просто `<img>`); `wide=` + `media=` — другой кадр на широких экранах; атрибут с пустым значением не выводится (кроме `alt`), поэтому `loading`/`fetchpriority` можно передавать переменной или через `yesno`; `as var` — чтобы показать заглушку, если фото нет. Отдельный URL — фильтр `obj|spec_url:"spec"`, фото для лайтбокса — `photo|lightbox_url`. Всё это не падает на отсутствующем или битом файле. `sizes` считаем от сетки (контейнер 1152 px, поля 16 px) — примеры в `catalog/home.html`, `content/gallery.html`.
- Swiper/GLightbox подключаются только там, где нужны: блоки `vendor_css`/`vendor_js` + `partials/vendor.html`. Если слайдер или лайтбокс ниже первого экрана (карусель отзывов на главной, полоса «Как это выглядит» — `content/partials/photo_strip.html`), стили подключаются в `<body>` прямо перед ним, а не в `vendor_css`, — иначе блокируют первую отрисовку.
- Выпадающие меню шапки на ПК («Услуги», «Связаться») — Alpine-компонент `hoverMenu` (`static/js/hover_menu.js`, подключён в `base.html` до Alpine): наведение на устройствах с мышью, клик на тач-экранах и с клавиатуры. Карточка отзыва — Alpine-компонент `reviewCard` (`static/js/review_card.js`, тоже до Alpine): длинный ли отзыв, перемеряется при каждой смене ширины (`ResizeObserver`: при первом заходе на главную Alpine меряет раньше, чем Swiper разложит слайды), «Читать полностью» плавно анимирует `max-height`, затухание низа — переход зарегистрированного свойства `--review-fade` (`tailwind/source.css`).
- HTML-ответы получают ETag и 304 через `ConditionalGetMiddleware`, поэтому в публичных шаблонах не должно быть значений, меняющихся от запроса (CSP nonce, CSRF-токен), иначе 304 перестанут работать. Яндекс Карта на `/contacts/` грузится по клику (Alpine `x-if`), а не вместе со страницей.
- Фото первого экрана — без `loading="lazy"`, LCP-фото — с `fetchpriority="high"` (на главной без фото в шапке — первый ряд карточек категорий, см. `catalog/partials/category_card.html`). Логотип в шапке — из «Настройки сайта → Логотип» (`SiteSettings.header_logo`, спека `header_logo_img`: WebP без потерь высотой 132 px — 3× от 44 px в шапке; ширина `<img>` — по пропорциям из `header_logo_width/height`; `SizedProcessedImageField` в `fields.py` чинит эти поля у imagekit на Django 6), без него или при битом файле — `static/img/logo-header.png` (3× от 119×44, квантованный PNG ~3 КБ: грузится вместе с LCP-фото; контекст `header_logo`; снизу прозрачное поле высотой с выступ солнца — надпись на оси кнопок шапки).
