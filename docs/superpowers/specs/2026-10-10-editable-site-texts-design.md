# Редактируемые тексты сайта с историей изменений

Дата: 2026-10-10. Статус: дизайн согласован в чате, ждёт проверки спецификации.

## Цель

Короткие тексты витрины — лиды, подсказки, призывы, пустые состояния, заголовки блоков — сейчас зашиты в шаблоны,
и для правки «Бронируйте заранее — в тёплый сезон даты разбирают быстро.» нужен программист. Нужно:

1. собрать такие тексты и сделать их редактируемыми в админке;
2. перенести текущие формулировки миграцией — после неё сайт выглядит как раньше;
3. хранить историю изменений каждого текста: кто, когда, что было и что стало, с возвратом любой версии.

Критерий успеха: администратор находит текст по странице или по словам, правит его, видит результат на сайте,
открывает историю и возвращает прежнюю версию — без участия программиста.

## Границы

**Входят** (48 текстов, полный перечень — ниже): лиды страниц, подсказки, призывы связаться (`cta_card`, блок
«Оставить отзыв»), пустые состояния, текст баннера cookie, страница 404 и заголовки разделов страниц (`h2`,
надзаголовок «Основатель», заголовок на главной).

**Не входят:**

- кнопки и ссылки («Читать полностью», «Построить маршрут», «Все мероприятия»), aria-подписи и `alt`;
- заголовки `h1` страниц, совпадающие с пунктами меню («Контакты», «Галерея», «О нас», «Мероприятия», «Отзывы»), —
  иначе меню и заголовок разойдутся;
- подписи полей («Стоимость», «Когда», «Где», «Адрес», «Координаты для навигатора»), заголовки колонок подвала,
  статус «Мероприятие уже прошло.», подпись «Гость Т-Парка»;
- заголовки с подстановкой («Ещё в категории «…»»);
- `500.html`: Django рендерит её без контекста и без запросов к БД (ошибка часто в самой БД) — отредактированный
  текст там всё равно не показался бы;
- тексты, уже редактируемые в «Настройках сайта» (вступления, «О нас», биография), и их история — см.
  «Тексты в настройках сайта» ниже.

## Решения

| Вопрос | Решение |
|---|---|
| Объём | Содержательные тексты + заголовки блоков; кнопки и служебные подписи — в шаблонах |
| История | Только для новых текстов: просмотр версий и возврат |
| Механизм истории | `django-simple-history` + `unfold.contrib.simple_history`; запасной план — своя модель версий |
| Где код | Новое приложение `apps/texts` |
| Формат | Простой текст без HTML; ссылки и подстановки остаются в шаблоне |
| Пустое значение | Обязательный текст (заголовки) пустым не сохранить; необязательный пустой — блок скрыт |
| Тексты из `SiteSettings` | Остаются на месте; в админке — взаимные подсказки, история для настроек — возможный следующий шаг |

## Архитектура

### Реестр — `apps/texts/registry.py`

Источник правды о наборе текстов: кортеж описаний `TextDef(key, label, default, where, required)`.

- `key` — `"<страница>.<имя>"`, например `service.booking_hint`; уникален, не меняется.
- `page` — раздел для фильтра в админке: префикс ключа до точки, значение из `Page` (`TextChoices`): Главная, Услуга, Категория,
  Мероприятия, Мероприятие, О нас, Контакты, Отзывы, Галерея, Страница 404, Общее (блоки на нескольких страницах).
- `label` — понятная подпись в админке («Подсказка под ценой»).
- `default` — текущая формулировка из шаблона; её выводит сайт, пока записи нет, и её показывает админка как
  «Текст по умолчанию».
- `required` — заголовки и тексты, без которых ломается вёрстка; остальное можно очистить, чтобы скрыть блок.
- `where` — где текст на сайте («Страница услуги, под ценой»), подсказка в админке.

Порядок описаний в реестре — порядок на странице сверху вниз; из него берётся поле `order`.

### Модель — `apps/texts/models.py`

`SiteText`: `key` (CharField, unique), `page` (CharField с `choices=Page`), `label`, `text` (TextField,
`blank=True`), `order` (PositiveIntegerField), `updated_at` (auto_now), `history = HistoricalRecords()`.
Сортировка — `order` (реестр уже сгруппирован по страницам). `__str__` — «Страница: подпись».

`required` и `default` в БД не дублируются: их берут из реестра по `key` (форма админки, тег).

### Вывод на сайте

- **Контекст-процессор** `apps.texts.context_processors.site_texts` кладёт в контекст `site_texts` — ленивый
  объект (`SimpleLazyObject`), который при первом обращении одним запросом читает все тексты в словарь
  `key → text`. Страница, не использующая тексты, запросов не делает. Кеша между запросами нет: один запрос на
  ~50 строк дешевле, чем инвалидация кеша на нескольких воркерах gunicorn.
- **Тег** `{% load site_texts %}`, `{% text "service.booking_hint" %}` и `{% text "about.cta_title" as title %}`
  (вариант с `as` — для передачи в `{% include "partials/cta_card.html" with title=title %}` и для
  `{% if %}` вокруг необязательных блоков).
  - Ключ — строковый литерал; ключ не из реестра — `TemplateSyntaxError` при компиляции шаблона (ловят тесты
    страниц).
  - Значение: текст из БД; если записи нет или в контексте нет `site_texts` (рендер без контекст-процессоров) —
    `default` из реестра. Пустой необязательный текст возвращается пустым — шаблон скрывает блок через
    `{% if %}`; пустой обязательный (форма такого не пропустит, но мог появиться в обход) — `default`.
  - Вывод экранируется и проходит через фильтр `nobr` (`apps/core/templatetags/site_tags.py`), поэтому
    «Т-Парк» не разрывается по дефису; ручные `<span class="whitespace-nowrap">Т-Парк</span>` в этих фразах
    больше не нужны. С `as` в переменную кладётся обычная строка: её выводят с `|nobr` (`cta_card` уже так
    делает) — иначе `nobr` применился бы дважды.
- **Шаблоны.** Литералы заменяются тегом. Фразы с условием делятся на ключи: пустое состояние мероприятий —
  `events.empty_vk_text` («Анонсы первыми появляются…», только при ссылке на ВКонтакте) и `events.empty_text`.
  Ссылки и подстановки остаются в шаблоне: телефон после `error404.call_text`, ссылка на политику после
  `common.cookie_text`, счётчик после `gallery.lead` и `reviews.lead`.

### Админка — `apps/texts/admin.py`

Пункт «Тексты сайта» в группе «Сайт» бокового меню (`UNFOLD["SIDEBAR"]`).

- Класс — `SiteModelAdmin` (предупреждение о несохранённых изменениях) вместе с `SimpleHistoryAdmin` из
  `unfold.contrib.simple_history`.
- Список: `label`, `page`, начало текста, `updated_at`; фильтр по `page`; поиск по `label` и `text`;
  сортировка — как на сайте.
- Карточка: поле `text` (textarea); только для чтения — `key`, `page`, «Где на сайте», «Текст по умолчанию»;
  у необязательных — подсказка «Пусто — блок на сайте скрыт».
- Форма запрещает пустой `text` у обязательных текстов.
- Добавлять и удалять нельзя (`has_add_permission`/`has_delete_permission` → `False`): набор задаёт реестр.
- Над списком — подсказка: «Вступления и длинные тексты страниц («О нас», биография, «Что рядом», текст
  контактов) — в «Настройках сайта»» со ссылкой на них.

### Тексты в настройках сайта

Текстовые поля `SiteSettings` (`home_intro`, `events_intro`, `contacts_text`, `about_motto`, `about_text`,
`founder_name`, `founder_lead`, `founder_text`, `nearby_text`) в новую систему **не переносятся**:

- шесть из девяти — длинный HTML в prose-editor с очисткой nh3, а `SiteText` — короткие фразы без разметки;
  поддержка обоих видов усложнила бы модель и форму;
- они используются не только в шаблонах: описание сайта по умолчанию и JSON-LD (`context_processors.py`,
  `structured_data.py`), SEO-подсказки страниц (`seo.py`), импорт старой базы (`legacy/site.py`) — перенос
  затронул бы всё это без видимой пользы;
- страница «О нас» редактируется в одной вкладке настроек вместе с фото, фактами и форматами — дробить её не стоит.
  Короткие `about_motto`, `founder_name`, `founder_lead` остаются там же по той же причине.

Изменения в админке настроек (`apps/core/admin.py`):

- вкладка «Тексты» (`events_intro`, `contacts_text`) переименовывается в «Мероприятия и контакты» — чтобы не
  путать с пунктом меню «Тексты сайта»;
- в описании вкладок «Главная», «Мероприятия и контакты» и «О нас» — подсказка: «Заголовки блоков и короткие
  фразы страницы — в «Текстах сайта»» со ссылкой на список, отфильтрованный по странице (у «О нас» — дополнение
  к уже существующему описанию про форматы и цифры основателя).

**Возможный следующий шаг (не в этом объёме):** история для «Настроек сайта» — `HistoricalRecords()` на
`SiteSettings` (и при желании `InfoPage`), после того как `django-simple-history` подтвердит совместимость.
Оговорка: версия настроек — снимок всех полей, «Вернуть» откатывает и поля, изменённые позже (адрес, ссылки);
это нужно показать в подсказке на странице истории или ограничиться просмотром версий.

### История

- `django-simple-history`: `HistoricalRecords()` на `SiteText`, `simple_history.middleware.HistoryRequestMiddleware`
  (автор правки), `unfold.contrib.simple_history` и `simple_history` в `INSTALLED_APPS` (порядок — по
  документации Unfold).
- В карточке текста — кнопка «История»: версии с автором, датой и изменившимися полями. Открыв версию,
  «Вернуть» сохраняет её как новую версию — откат тоже попадает в историю и его можно отменить.
- Недостающие русские строки интерфейса истории — в `locale/ru/LC_MESSAGES/django.po` (как для Unfold), затем
  `compilemessages`.
- **Проверка совместимости — первый шаг реализации.** `django-simple-history` 3.13 официально заявляет
  Django ≤ 6.0, у нас 6.1. Ставим пакет, проверяем миграции, запись версий с автором и возврат через админку
  тестами. Если не работает — остановиться, сообщить и перейти на запасной вариант: своя модель
  `SiteTextRevision` (старое и новое значение, автор, дата), таблица версий в карточке и кнопка «Вернуть».
  Реестр, модель `SiteText`, тег и шаблоны от этого не меняются.

### Миграции и начальные данные

- `texts.0001_initial` — схема `SiteText` и `HistoricalSiteText`.
- `texts.0002_initial_texts` — data-миграция: `sync_texts(apps)` из `apps/texts/registry.py` создаёт
  недостающие записи из реестра (`text = default`) и каждой созданной — начальную версию в истории
  (тип `+`, без автора), чтобы первая правка показывала «было → стало». Существующие записи не трогает.
  Работает с историческими моделями миграций (как `apps/core/seo_content.py` и `privacy_defaults.py`).
- `import_legacy` вызывает `sync_texts` в конце, как `seo_content`: импорт с `--flush` не должен оставлять сайт
  без записей текстов.
- Новый текст в будущем: описание в реестре + тег в шаблоне + маленькая data-миграция, вызывающая
  `sync_texts`. До миграции сайт показывает `default` — ничего не ломается.

## Тесты

- **Тег:** текст из БД; без записи — `default`; без `site_texts` в контексте — `default` без запросов;
  неизвестный ключ — `TemplateSyntaxError`; `as` кладёт значение в переменную; пустой необязательный текст
  скрывает блок; «Т-Парк» оборачивается `nobr`, HTML в тексте экранируется.
- **Реестр ↔ шаблоны:** каждый ключ из `{% text "…" %}` в `templates/` есть в реестре, и каждый ключ реестра
  используется в шаблонах; ключи уникальны; `page` из `Page`.
- **Миграция:** после миграций для каждого ключа есть запись с `default` и одна начальная версия в истории;
  повторный `sync_texts` не трогает изменённые записи. Существующие тесты страниц, проверяющие эти фразы,
  проходят без изменений — сайт после переноса выглядит как раньше.
- **Запросы:** страница с текстами делает ровно один запрос к `SiteText` (`django_assert_num_queries`).
- **Админка:** правка создаёт версию с автором; возврат версии восстанавливает текст и создаёт новую версию;
  пустой обязательный текст не сохраняется; страниц добавления и удаления нет; список фильтруется по странице;
  в настройках сайта нет вкладки «Тексты», есть «Мероприятия и контакты», а подсказки ведут на «Тексты сайта»
  с фильтром по странице.
- **Изменение видно на сайте:** правка `service.booking_hint` меняет страницу услуги; очистка — убирает абзац.
- **500:** `500.html` рендерится без запросов к БД (не затронута).
