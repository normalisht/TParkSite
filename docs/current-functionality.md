# Текущий функционал сайта Т-Парка (Flask-версия)

Снимок состояния на 2026-10-08, сделан перед переписыванием на Django. Код старой версии лежит в `old_version/`, все пути ниже — относительно неё. Документ описывает то, что **есть сейчас**, включая костыли, — чтобы при миграции ничего не потерять и осознанно решить, что выкинуть.

## 1. Публичный сайт

Общий каркас всех страниц (`main/base.html`): шапка с меню категорий, контакты в подвале (адрес, ссылка на Яндекс.Карты, телефоны `tel:`, WhatsApp по первому номеру, Telegram, VK). Мобильная/десктопная версии выбираются на клиенте (`mobile-detect.js`), для мобильных есть свайпы (`hammer.js`).

| URL | Что показывает | Источник данных |
|---|---|---|
| `/`, `/TPark` | Главная: текст `main_text` + категории, сгруппированные по «группам категорий» (`Type`), отсортированные по `number`. Показываются только категории со `status=1`. | `Text`, `Type`, `CategoryType`, `Category` |
| `/category?category_id=N` | Страница категории: слайдер фото категории, описание (HTML), список услуг по порядку `ServiceCategory.number`. У услуги: название, цена («`price` руб / `time`»), раскрывающееся краткое описание **или** ссылка на отдельную страницу услуги (если `next=1`). Скрытая категория → редирект на главную. | `Category`, `ServiceCategory`, `Service`, файлы `../src/old_migrate/images/category/N/` |
| `/category/service?service_id=N` | Страница услуги: слайдер фото, цена, полное описание (HTML). Статус услуги **не проверяется**. | `Service`, `../src/old_migrate/images/service/N/` |
| `/events` | Мероприятия: слайдер с фото из `../src/old_migrate/images/events/` + карусель мероприятий. Будущие (дата > сегодня 22:00) идут первыми, прошедшие показываются только с флагом `after_date`. Если мероприятий < 3, список дублируется ×3 для карусели. У мероприятия: заголовок, дата, описание, ссылка (соцсеть/внешний сайт), цвет текста. | `Event`, `../src/old_migrate/images/events/` |
| `/about_2` | «О нас»: тексты `about`, `filosofi` (философия), `structure` (что рядом), карта `../src/old_migrate/images/staff/map_about.jpg`, сотрудники (фото, имя, должность), партнёры (логотип + ссылка). | `Text`, `Employee`, `Partner` |
| `/reviews` | Отзывы: имя, текст, опциональное фото `../src/old_migrate/images/comments/<id>.jpg`. Порядок полуслучайный (сортировка по длине → две колонки → shuffle). | `Comment` |
| `/gallery` | Галерея: все файлы из `../src/old_migrate/images/gallery/`. | только файлы |
| `/contacts` | Контакты: текст `contacts_info`, карта `../src/old_migrate/images/staff/map.jpg`, общие контакты. | `Text` |
| `/info?info_id=N` | Произвольная инфо-страница (например «Правила безопасности»). Если `status=0` — «Доступ к странице закрыт». Ссылки на эти страницы нигде в меню нет — раздаются вручную. | `Text` (записи без `title`) |

## 2. Админка (`/admin_panel`, самописная)

Вход по email + пароль (`Admin`, пароль хранится открытым текстом), сессия «запомнить меня». Все страницы за `login_required`. HTML-поля редактируются через CKEditor.

| Раздел | Возможности |
|---|---|
| **Категории** (`/category`, `/category_change`, `/category_create`) | Список по порядку. Создание: название, описание, пачка фото. Редактирование: название (авто-`capitalize`), описание, порядок (`number`, «вес»), видимость (`status`), порядок услуг внутри категории, отвязка услуг, добавление/замена/удаление фото слайдера, превью для главной (`../src/old_migrate/images/category/preview/N.jpg`, 1080×720), удаление категории вместе с папкой фото. |
| **Услуги** (`/all_services`, `/service_test`, `/service_create`) | Список по алфавиту. Создание/редактирование: название, краткое описание, полное описание, цена (строка), единица времени (строка, «час», «сутки»…), флаг «отдельная страница» (`next`), привязка к нескольким категориям чекбоксами, фото слайдера (добавить/заменить/удалить с перенумерацией файлов), удаление услуги. Новая услуга создаётся с `status=1`; переключателя видимости услуги в UI нет. |
| **Группы категорий** (`/category_types`, `/edit_category_type`, `/category_type_create`) | Название, порядок, набор категорий (чекбоксы), удаление. |
| **Мероприятия** (`/events`, `/event_create`, `/event_edit`) | Разделены на предстоящие и прошедшие. Поля: заголовок, дата, описание, ссылка, цвет текста, «показывать после даты», одно фото (`../src/old_migrate/images/events/<id>.jpg`). Удаление. |
| **Страница событий** (`/events_content`) | Редактирование `main_text` и до трёх фото фонового слайдера (`../src/old_migrate/images/events/0..2.jpg`). Пункта меню нет. |
| **О нас** (`/about_2`) | Тексты about/filosofi/structure, карта, партнёры (добавить с логотипом, сменить ссылку/логотип, удалить). Для добавления используется служебная запись `Partner(name="temp")`, которую публичная страница удаляет при каждом заходе. **Сотрудники в админке не редактируются.** |
| **Отзывы** (`/comments`, `/edit_comment`, `/comment_create`) | Имя, текст, фото; удаление. |
| **Галерея** (`/gallery`) | Загрузка пачкой (имена — следующий номер), удаление по одному. |
| **Контакты** (`/contacts`) | Текст `contacts_info`, карта. Адрес, телефоны, VK, геоссылка (`Text` с соответствующими `title`) в UI **не редактируются** — только через БД. |
| **Инфо-страницы** (`/all_info_page`, `/info_create`, `/info`) | Создание/редактирование HTML-текста, флаг публикации, удаление, показ публичной ссылки. Список — все `Text` с `id > 10` (захардкожено). |

Все загружаемые изображения пережимаются Pillow до ≤1920×1080 (галерея — quality 70, превью категорий — 1080×720 q80, остальное — q95) и сохраняются как `.jpg`.

### Ключи `text.title`

`main_text`, `about`, `filosofi`, `structure`, `contacts_info`, `address`, `phone_numbers` (через пробел, без `+7`), `vk`, `insta` (фактически ссылка на Telegram), `geolocation` (ссылка на Яндекс.Карты). Записи без `title` — инфо-страницы.

## 4. Известные проблемы текущей версии

- Пароль админа в открытом виде; SMTP-креды закоммичены в `config.py`/`.flaskenv`.
- Нет CSRF-защиты форм админки.
- Изображения вне БД: при удалении/перенумерации легко рассинхронизировать; имена `events/0..2.jpg` конфликтуют с фото мероприятий с id 0–2.
- Страница услуги не проверяет `status`; переключателя видимости услуги нет.
- Сотрудники, адрес, телефоны, соцсети не редактируются из админки.
- Голые `except:` повсюду, ошибки молча проглатываются.
- Мобильная вёрстка определяется по User-Agent на клиенте → мигание стилей, дублирование CSS.
- Таблица `price` и модель `Price` мертвы; шаблоны `main/main.html` (используется для `/events`) и `main/new_main.html` (главная) названы путано.
