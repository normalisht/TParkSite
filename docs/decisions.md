# Переписывание сайта Т-Парка: договорённости

Журнал принятых решений по новой версии. Из него собирается спецификация. Текущий функционал описан в [current-functionality.md](current-functionality.md), старый код лежит в `old_version/`.

Статус: проектирование завершено, все разделы согласованы. Полная спецификация: [superpowers/specs/2026-10-08-django-rewrite-design.md](superpowers/specs/2026-10-08-django-rewrite-design.md) — она первична; ниже краткий журнал решений.

## Цель

Переписать сайт на Django и сохранить текущий функционал: витрину категорий и услуг, мероприятия, отзывы, галерею, «О нас», контакты, инфо-страницы. Улучшить дизайн и удобство как сайта, так и админки.

**Объём (вариант A):** функционал прежний, новых бизнес-функций нет. Заявки по-прежнему идут через телефон, WhatsApp и Telegram. Онлайн-бронирования, оплаты, форм заявок и личного кабинета нет.

## Принятые решения

| # | Решение | Почему |
|---|---|---|
| 1 | **Бэкенд: Django**, админка на Django admin | Готовая админка вместо самописной |
| 2 | **Фронт: Django-шаблоны**, без React/SPA | Контентный сайт; страница рендерится на сервере, что важно для SEO; не нужны DRF, Node и второй контейнер |
| 3 | **Вёрстка: Tailwind CSS через `django-tailwind-cli`** (standalone-бинарник, без Node). UI-кит (daisyUI и т.п.) не используем, компоненты пишем сами | Собственный вид вместо шаблонного; адаптивность через классы вместо отдельных `*_phone.css` и `*_desktop.css` |
| 4 | **JS: Swiper** (слайдеры), **GLightbox** (галерея), **Alpine.js** (аккордеоны, меню). jQuery, hammer.js и mobile-detect.js убираем | Подключаются без сборки; мобильная версия делается через media queries, а не через User-Agent |
| 5 | **Админка: `django-unfold`** | Современный вид, удобна с телефона |
| 6 | **Сортировка перетаскиванием: встроенная в Unfold** (`ordering_field`). `django-admin-sortable2` подключаем, только если её не хватит | Меньше зависимостей, нет конфликтов стилей и JS с Unfold |
| 7 | **HTML-редактор:** преемник CKEditor 4. Кандидаты: `django-prose-editor`, `django-tinymce` или встроенный в Unfold. Выбираем при проектировании админки | CKEditor 4 больше не поддерживается |
| 8 | **Фото — отдельные модели с полем порядка**, редактируются внутри формы записи. Миниатюры и WebP через `django-imagekit` или `sorl-thumbnail` | Связь «запись ↔ фото» хранится в БД, а не в именах файлов; перенумерация файлов не нужна |
| 9 | **БД: SQLite** | Небольшой объём, один сервер |
| 10 | **Медиа: том Docker**, без MinIO. Хранилище настраивается через `STORAGES`, чтобы при необходимости перейти на S3 через `django-storages` только конфигом | MinIO — лишний сервис и бэкап при объёме в сотни МБ; у community-версии MinIO сейчас проблемы с распространением |
| 11 | **Запуск: docker compose.** На сервере уже работает общий reverse-proxy (nginx или Traefik), HTTPS настраивает он | Вариант B по инфраструктуре |
| 12 | **Состав compose:** `web` (Django + gunicorn, статика через WhiteNoise) и `media` (nginx, отдаёт `/media/` из тома). Оба подключены к внешней сети прокси, порты наружу не открываются. Тома: `db` (SQLite), `media` | Django не отдаёт медиа в продакшене |
| 13 | **Бэкап:** снимок SQLite через `sqlite3 .backup` + архив тома `media` | Всё состояние сайта лежит в двух томах |
| 14 | **Зависимости: uv** (`pyproject.toml` + `uv.lock`) | Пожелание владельца проекта |
| 15 | **Дизайн:** сохраняем узнаваемость текущего сайта (логотип, цвета, общее настроение), вёрстку и компоненты делаем заметно современнее | Вариант B с уклоном в C |
| 16 | **Перенос данных: management-команда `import_legacy`**. Читает старую SQLite через `sqlite3` и папку `images/`, раскладывает данные по новой схеме. Идемпотентна (запуск на чистой БД), сохраняет старые `id` категорий, услуг и инфо-страниц | Позволяет улучшить модель данных; можно прогонять сколько угодно раз до финального переезда |
| 17 | **Старая модель `Text` разносится** на настройки сайта (адрес, телефоны, соцсети, геоссылка), тексты страниц и инфо-страницы | Сейчас в ней всё вместе, а настройки нельзя редактировать из админки |
| 18 | **Таблицу `price` не переносим**, её содержимое выгружаем в CSV рядом с бэкапом | В коде не используется |
| 19 | **Старые URL отдают 301-редиректы** на новые (`/category?category_id=N` → `/category/N-slug/` и т.д.) | Сохраняем позиции в поиске и внешние ссылки |
| 20 | **Пароль админа не переносим**, учётная запись создаётся через `createsuperuser` | В старой БД пароль хранится открытым текстом |
| 21 | **У услуги появляется переключатель видимости**, публичная страница его учитывает | Сейчас статус услуги не проверяется и не редактируется |
| 22 | **Старый проект перенесён в `old_version/`** (`git mv`, история сохранена). Новый проект создаётся в корне репозитория | Удобно разрабатывать и обращаться к старому коду и БД для импорта |
| 23 | **Стек: Python 3.13 + Django 6.1.2** (`django>=6.1.2,<6.2`) | Выбор владельца проекта. Совместимость с Unfold, prose-editor, imagekit и tailwind-cli проверена smoke-тестом (2026-10-08). 6.1 не LTS — при выходе 6.2 LTS обновиться |
| 24 | **Телефоны — отдельная модель `Phone`** (номер, порядок, `is_whatsapp`, `is_telegram`), inline в настройках сайта. Флаг каждого мессенджера — не более чем у одного номера (частичный `UniqueConstraint` + валидация). Ссылки `wa.me/7…` и `t.me/+7…` строятся из номера, отдельного поля Telegram нет | Номера и мессенджеры редактируются в одном месте |

## Модели (согласовано)

Приложения: `core`, `catalog`, `content`.

- **core:** `SiteSettings` (синглтон; адрес, ссылка на Яндекс.Карты, VK, тексты главной, событий, «О нас», «Философии», «Что рядом», контактов, две картинки карт), `Phone` (см. решение 24), `InfoPage` (заголовок, slug, HTML, «опубликовано»).
- **catalog:** `CategoryGroup` (название, порядок, M2M на категории), `Category` (название, slug, описание, «опубликовано», порядок, превью), `CategoryPhoto` (порядок), `Service` (название, slug, краткое и полное описание, цена и единица времени строками, «опубликовано», «отдельная страница»), `CategoryService` (through-модель с порядком), `ServicePhoto` (порядок).
- **content:** `Event` (заголовок, дата, описание, ссылка, необязательный цвет текста, «показывать после даты», фото), `Review` (имя, текст, фото, «опубликовано», порядок), `Partner` (название, ссылка, логотип, порядок), `Employee` (имя, должность, фото, порядок), `GalleryPhoto` (фото, подпись, порядок).
- Порядок везде — поле `order` с перетаскиванием в Unfold; изображения — `ImageField`; файлы удаляются вместе с записью.
- Импорт: первому старому номеру ставится `is_whatsapp`, номеру 9953056461 — `is_telegram`. Заголовки `InfoPage` берутся из первого жирного или заглавного фрагмента текста.

## Публичные страницы (согласовано)

### URL и редиректы

| Страница | URL | 301 со старого |
|---|---|---|
| Главная | `/` | `/TPark` |
| Категория | `/category/<slug>/` | `/category?category_id=N` |
| Услуга (только с «отдельной страницей») | `/service/<slug>/` | `/category/service?service_id=N` |
| Мероприятия | `/events/` | — |
| О нас | `/about/` | `/about_2` |
| Отзывы | `/reviews/` | — |
| Галерея | `/gallery/` | — |
| Контакты | `/contacts/` | — |
| Инфо-страница | `/info/<slug>/` | `/info?info_id=N` |

- Slug — транслитерация названия, редактируется в админке.
- Неопубликованная категория или услуга, а также услуга без «отдельной страницы» → 404.

### Каркас

- Шапка: логотип и меню «Услуги» (выпадающий список категорий по группам), «Мероприятия», «О нас», «Отзывы», «Галерея», «Контакты». На телефоне — бургер.
- Подвал: адрес со ссылкой на карту, все телефоны, иконки WhatsApp, Telegram, VK.
- На телефоне плавающая кнопка «Связаться»: позвонить, WhatsApp, Telegram.

### Страницы

- Главная: вступительный текст и блоки групп с карточками категорий (превью).
- Категория: слайдер фото, описание, услуги с ценой «X руб / время»; краткое описание раскрывается аккордеоном, а при «отдельной странице» карточка ведёт на страницу услуги.
- Услуга: слайдер, цена, полное описание, кнопки связи.
- Мероприятия: сначала предстоящие, затем прошедшие с флагом «показывать после даты»; карусель Swiper с бесконечной прокруткой (без дублирования ×3). **Отдельный фоновый слайдер убран**: в шапке страницы вступительный текст и фото ближайшего мероприятия.
- О нас: тексты, карта, сотрудники, партнёры.
- Отзывы: сетка в стиле masonry, **порядок задаётся вручную** (поле `order`).
- Галерея: сетка миниатюр + лайтбокс.
- Контакты, инфо-страницы, 404 и 500 в общем стиле.

### SEO

`<title>` и `meta description` у каждой страницы, Open Graph, `sitemap.xml` (`django.contrib.sitemaps`), `robots.txt`.

## Админка (согласовано)

### Общее

- Unfold, русский интерфейс, вход по `/admin/`, стандартные пользователи Django.
- Боковое меню: **Каталог** (группы, категории, услуги), **Контент** (мероприятия, отзывы, галерея, партнёры, сотрудники), **Сайт** (настройки, инфо-страницы), **Доступ** (пользователи).
- Миниатюры фото в списках и формах; «Смотреть на сайте» у категорий, услуг и инфо-страниц.

### Разделы

- **Настройки сайта** — синглтон без создания и удаления; вкладки «Контакты» (+ inline телефонов), «Тексты», «Карты».
- **Категории** — список с превью, переключателем публикации и перетаскиванием; форма с вкладками «Основное», «Фото» (inline + загрузка пачкой), «Услуги» (inline `CategoryService` с автодополнением и перетаскиванием).
- **Услуги** — поиск, фильтры (категория, «опубликовано», «отдельная страница»); фото (inline + пачкой), категории (inline `CategoryService`).
- **Группы категорий** — порядок перетаскиванием, категории через `filter_horizontal`.
- **Мероприятия** — фильтр «Предстоящие / Прошедшие», `date_hierarchy`, превью фото.
- **Отзывы, партнёры, сотрудники** — фото и порядок перетаскиванием.
- **Галерея** — миниатюры, перетаскивание, кнопка «Загрузить фото пачкой».
- **Инфо-страницы** — заголовок, slug, текст, «опубликовано».
